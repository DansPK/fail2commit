## Outcome, export, and fallback authority

`sandbox/mod.rs:74-87` probes before running and exports declared host files only after the backend returns `Exited(0)`. With the current early VM run refusal, the normal VM path cannot return that status and cannot reach export. The dormant VM outcome reader (`vm/windows.rs:662-684`) bounds and decodes the outcome; the decoder rejects a guest `exported` claim (`hardened/protocol.rs:328-360`). No outcome identity or WSB attestation was added, and the dormant launcher-exit acceptance is still insufficient for export authority if the early gate is removed.

`vm/windows.rs:47-58` still falls back to the platform backend only for `ProbeFailure::Absent` (feature disabled or firmware virtualization absent at `:109-128`); a failed preflight stays selected and unavailable. That documented absence fallback is distinguishable through `PlatformFallback`'s probe detail/control (`vm.rs:33-49`). The unsupported lifecycle itself is not routed to fallback, which is correct for fail-closed selection, but the ready probe must report it unavailable. Direct `--vm-guest` uses the platform backend independently of this selection and remains VW-03.
