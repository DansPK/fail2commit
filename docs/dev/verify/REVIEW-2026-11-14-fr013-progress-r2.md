## Remaining findings

1. **High — result child retains inherited stdout/stderr pipes.** `crates/fail2commit/src/cmd/progress_ui.rs:237-245`, `crates/fail2commit/src/main.rs:113-139`. `Command::new(current_exe()).spawn()` leaves standard streams inherited by default. With an interactive Windows desktop and stdout piped to a caller (for example a terminal pipeline or a process using `wait_with_output` without `--json`), a finding/error spawns the result-window child, which retains the write end of stdout until the person closes the window. The CLI process may exit, but the downstream reader never sees EOF and can remain blocked, recreating the user-visible nonblocking defect. Redirect the helper's stdin, stdout and stderr to null before spawning; the helper has no protocol output to return. Add a process-level test that captures a parent's stdout and proves EOF arrives while the result window remains open.

2. **Medium — pip's streaming done count includes resolver candidates outside the final plan.** `crates/fail2commit-core/src/pip/proxy.rs:163-180,227-243,303-311`, `crates/fail2commit-core/src/pip/mod.rs:273-288`. Each first verified `ensure` increments `completed_downloads`, including wheels fetched so pip can inspect a candidate's metadata during resolution. When backtracking selects a different version, that verified candidate is absent from the final `PlanWheel` list; the live `done/0` count has included a package that will not be installed. The final `step(DownloadVerify, wheels.len())` resets the counter and immediately marks all final wheels complete, masking this during short runs. Trigger with an index whose dependency metadata makes pip fetch and reject one candidate before settling on another. Keep streaming download *activity* visible, but count final-plan completions only once the plan is known, or label the pre-plan count as fetched candidates and reconcile explicitly without presenting it as packages of the plan. The existing `pip/proxy.rs:464-490` test calls the counter helper with one accepted wheel; it does not exercise resolver backtracking or compare streaming count with the final plan.
