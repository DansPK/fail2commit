## New findings

1. **High, VW-01 — launcher exit is treated as VM death without a bound VM lifecycle.** `vm/windows.rs:324-360` starts `WindowsSandbox.exe`, waits only for that `Child` via `try_wait` (`:655-665`), and accepts a valid outcome after its exit. `terminate_process_tree` targets that PID and its descendants through `taskkill /T` (`:669-713`). The code never identifies or waits for the Windows Sandbox VM/compute system itself; a launcher that exits while its VM remains active permits host `run_job` to export after `Exited(0)` (`sandbox/mod.rs:69-82`), and timeout cleanup can leave the VM alive. This is a boundary proof gap, not a claim that a particular WSB version detaches. **Fix:** use a WSB lifecycle signal tied to this instance or a verified containment/termination mechanism, and gate outcome acceptance, pin release and export on its confirmed shutdown; on uncertain termination fail closed and retain protective state. Exercise launcher-exit-before-guest-exit and timeout in real WSB.

2. **Medium, VW-02 — a representability error occurs after VM spawn with no cleanup.** `vm/windows.rs:324-335` spawns the sandbox before calling `timeout_deadline(job.limits.timeout)`, then `?` returns if `Duration::checked_add(BOOT_GRACE)` fails (`:795-797`). `JobLimits::from_settings` takes `limits.job_timeout_secs` as a `u64` with no apparent upper bound (`isolation.rs:27-30`, `settings.rs:152`), so a sufficiently large configured timeout can leave a launched VM and pinned mappings behind. **Fix:** validate and calculate every deadline before spawn; add overflow regression and assert no child was started.

3. **Medium, VW-03 — hidden guest dispatch is not bound to a VM context.** The public CLI dispatches `--vm-guest` directly (`main.rs:170-220`, `cmd/sandbox.rs:131-143`); `vm_guest.rs:17-29` derives an ID from path spelling and sets `FAIL2COMMIT_HOME=C:\f2c`, then `:59` always chooses the platform backend. A caller able to arrange the fixed `C:\f2c\control\<hex>\job.json` tree can invoke this path outside WSB, bypassing configured hardened-backend selection. The current host package workflow does not call this flag, so direct evasion of package approval is **not demonstrated**; nevertheless the flag's hidden status and path spelling are not guest authentication. **Fix:** require a trusted guest bootstrap/context capability before this dispatch, and verify package entry points cannot select it. Test outside-WSB invocation with a syntactically valid fixed control tree.

4. **Medium, VW-04 — feature query can hang before bounded output inspection.** `vm/windows.rs:169-205` pipes PowerShell stdout/stderr, waits for process exit before reading either stream, and enforces `MAX_CONTROL_OUTPUT` only afterward. A noisy query/error can fill a pipe and block the child until the 20-second timeout; the timeout path ignores cleanup failure (`:184-190`), so query descendants may remain. **Fix:** drain both streams concurrently with byte caps during the wait, and require termination confirmation on timeout. Test an injected child that fills both pipes.

## Source acceptance limits and checks

The host creates fresh control/result directories outside the package work mapping (`vm/windows.rs:272-300`), writes the request with `create_new` and `sync_all` (`:613-623`), and reads an opened, bounded outcome only after its tracked child exits (`:626-648`). The decoder rejects nonempty guest `exported` (`hardened/protocol.rs:328-360`), and guest publication uses `persist_noclobber` (`vm_guest.rs:59-70`). This is useful source structure, but the outcome has no embedded job identity or authenticated VM attestation; its trust depends on the result mapping ACL and VW-01 lifecycle proof. The read-only install-folder mapping (`vm/windows.rs:254-269,288-299`) maps the entire current-executable directory; verify in WSB that the untrusted AppContainer cannot read unrelated install files or the control/result mappings. WSB XML escaping, fixed guest ID, and explicit mapping modes are unit-tested, but mapping count/config size and actual WSB interpretation have no runtime gate.
