## Exact guest layout (CR-026 Linux correction)

Fixed outer-guest namespace, **outside** the inner Bubblewrap control mount
`/f2c` (which is bound last and would otherwise shadow any job tree under it):

| Guest mount | Host source | Mode |
|---|---|---|
| `/usr`, `/lib`, `/lib64`, `/bin`, `/sbin` (real dirs only) | same host path | read-only 9p system share |
| `/mnt/fail2commit-vm/jobs/<id>/work` | job `work_dir` | read-write (only writable job tree) |
| `/mnt/fail2commit-vm/jobs/<id>/input-<n>` | each staged read-only input | read-only |
| `/mnt/fail2commit-vm/control/<id>/job.json` | per-run control dir | read-only request |
| `/mnt/fail2commit-vm/results/<id>/outcome.json` | per-run result dir | result exchange |
| `/mnt/fail2commit-vm/bin/{fail2commit,f2c-sandbox-relay}` | initramfs copies | launcher |

`<id>` = fresh 32-hex identity on the kernel command line (`f2c_job_id=<id>`,
`f2c_uid=<uid>`, `f2c_gid=<gid>`). Merged-/usr symlinks are recreated in the
initramfs, not shared. The package's inner sandbox is granted neither the
request nor the result tree.

## Security properties implemented

- Explicit virtio-mmio devices (`virtio-9p-device`, `virtio-net-device`); no PCI
  `-virtfs` shorthand (CR-025). Prepare verifies QEMU `microvm` + device support
  and the 8-transport device budget (system shares + work/control/result/net +
  input slots).
- `security_model=passthrough`; guest launcher drops to the invoking uid/gid so
  guest writes match host ownership and system binaries keep real root ownership
  for the inner `trusted_exe` check.
- Initramfs from trusted root-owned binaries + **parsed** ELF `DT_NEEDED`
  closure (no `ldd` execution); host kernel; guest `virtio_mmio`, `virtio_net`,
  `9p`, `9pnet_virtio` modules (built-in or copied with kmod). Only `ETC_ALLOW`
  entries copied — no root/home/secrets share.
- Protected state `/etc/fail2commit-vm.json` (root-owned, non-writable) with
  SHA-256 of kernel/initramfs/QEMU; probe verifies ownership + hashes; stale or
  corrupt preparation fails closed. `vm remove` is idempotent and refuses a
  symlink planted in place.
- Host validates one fail2commit-owned job stage, refuses symlink/hardlink
  escapes, re-walks and pins resolved mount identities (`O_PATH`, dev/ino)
  before spawn. Guest binds dispatch to the kernel boot id + KVM hypervisor and
  validates resolved mount/file identities.
- Additive identity-bound outcome envelope around the frozen `JobOutcome`
  (`encode_vm_outcome`/`decode_vm_outcome`); rejects stale/forged ids and export
  claims. No package-writable nonce used as authentication.
- QEMU spawned as a process-group leader; group `SIGKILL` at
  `limits.timeout + 45s` boot grace; export only after a valid identity-bound
  outcome **and** clean QEMU exit.
- Selection falls back to the platform backend **only** on proven KVM/hardware
  absence; missing preparation, `/dev/kvm` permission denial, hash mismatch and
  runtime errors stay selected and fail closed (`IsolationUnavailable`).
