## New findings

### EP-01 — High, preactivation: two failed IPv4/IPv6 UDP routes can be reported as a passing probe

`windows_effect_probe.rs:32-33,176-177` records whether direct UDP interface routes were refused. `failed_checks` lists both (`:112-117`), but `EffectResults::complete()` omits both (`:45-70`). The service accepts `complete()` plus exit zero (`service.rs:3889-3901`) and then sets `effect_probe_passed=true` (`:1998-2006`). Trigger: either `direct_udp_interface_v4_refused` or `direct_udp_interface_v6_refused` is false while the other fields are true; the child exits successfully, the service reports LPAC/WFP effects passed, and the backend exposes `wfp_lpac_traffic_effects=true` (`mod.rs:286-315`). The unit test builds both as true but never flips either (`windows_effect_probe.rs:293-338`), so its name overstates coverage. **Fix:** include both fields in `complete()`, test each independently as false, and verify both interface routes on the installed VM. This finding does not turn on Internet jobs in the pinned code; it makes the new diagnostic misleading.

### EP-02 — High, preactivation: failed preparation ACK bypasses checked WFP cleanup and marker retention

After `PackageGuard::install` succeeds, `service.rs:3106-3123` writes the preparation ACK with `?` *before* assigning the guard to `network_guard`. `write_prepare_ack` can return on a closed pipe or short `WriteFile` (`service.rs:1135-1165`). In that case the local guard is dropped; `PackageGuard::drop` discards `close()` errors (`windows_wfp.rs:747-751`). The outer cleanup only calls checked `guard.close()` when `network_guard` is `Some` (`service.rs:3286-3297`) and can clear the durable marker after confirmed tree termination (`:3315-3320`). Trigger: the launcher closes the ACK read end after successful WFP install, followed by a loopback-exemption removal, dynamic-session close, or filter readback failure. Cleanup may be unconfirmed while the service clears its active marker and does not latch refusal; a leaked raw WFP engine handle can retain dynamic filters until service exit. **Fix:** store the guard before any fallible ACK operation, route ACK errors through the common tree-termination and checked cleanup path, and retain the marker/latch on cleanup failure. Inject an ACK delivery failure followed by each cleanup failure and assert marker, journal, filter and subsequent-launch state.
