## Residual findings

### LP-01 — High, conditional: root-only ancestor can be traversed through a caller-selected stage

Although the stage root and descendants must be peer-owned, `collect_requests` unconditionally adds `--x` ACL requests on every ancestor of each caller root (`linux_acl.rs:515-527`), and `open_acl_target` accepts root-owned ancestors (`:682-705`). The service runs those ACL grants as root before Bubblewrap resolves and binds the requested tree (`service.rs:2031-2045`; `linux.rs:569-581,642-645`). Trigger: an administrator has created a peer-owned stage tree under a root-owned, non-traversable ancestor in an effectively writable permitted location (for example a private root directory under `/home`), and the peer knows the path. The peer cannot traverse the ancestor directly, but can submit its child path in the job envelope; the root service resolves it, grants the sandbox UID execute on the ancestor, and returns stage contents through job output. Peer ownership of the leaf does not prove the peer was authorized to reach it. **Fix:** verify the authenticated peer's effective traverse access to every caller-supplied ancestor before adding grants; retain an explicit trusted exception for fixed service-owned snapshot/probe ancestors. Add a root-only ancestor fixture where the leaf is peer-owned and assert rejection before ACL mutation. No root-installed reproduction was run.

### LP-02 — High availability/recovery: retained ACL journal loses its temporary target paths

`run_linux_service_job` creates a `TempDir` snapshot and journals its root/input/jobfile/output paths (`service.rs:1995-2045`). On unconfirmed scope inactivity it calls `grants.defer_recovery()` and returns (`:2126-2132`); on some later errors it also retains the journal (`:2159-2167`). Returning drops `snapshot`, deleting the paths while the journal remains. The fixed PROBE creates another `TempDir` for its peer-owned stage and propagates the same error with `?` (`service.rs:1219-1224,1315-1321`), deleting those journaled targets too. `recover` requires every recorded pathname and dev/inode/owner to exist before it restores any ACL (`linux_acl.rs:249-260,1058-1066`); a subsequent request or service restart therefore fails closed permanently, and uninstall recovery cannot complete. Trigger: a launched scope fails inactive readback, or a post-launch output ownership/fsync failure retains grants. **Fix:** keep both snapshot and probe-stage TempDirs durably whenever the ACL journal is retained; reconcile and remove them only after exact scope death and ACL restoration. Inject the unconfirmed-scope and post-launch failure paths, then verify real recovery and retry.

### LP-03 — Medium verification gap: the read-only fixture does not prove a read-only mount

The platform payload checks that `probe.txt` is readable and opening it for write fails (`service.rs:1409-1439`), then prints the pass marker; the service requires only that marker, exit zero, no exports and no truncation (`:1124-1136,1335-1340`). But the fixture is created mode `0400` and the sandbox receives only `r-x` ACL access to its read-only tree (`service.rs:1232-1241`; `linux_acl.rs:495-504`). The same write attempt fails even if that tree were accidentally bound writable. The pinned `linux.rs:642-645` does use `--ro-bind`, so this is a probe-coverage defect rather than evidence of a current writable bind. **Fix:** assert the mount's read-only flag from inside the sandbox or use a controlled fixture for which DAC/ACL permits write while the mount must deny it; require that check for platform completion.
