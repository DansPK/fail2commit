## Open items for the owner

1. **Windows default-mode UDP (HB-036/HB-037, blocks sign-off).** With AppContainer, scripts can send UDP to multicast (224.0.0.251, 239.255.255.250, ff02::1) and to limited/directed broadcast in both `none` and `internet` modes. Present at v0.1.3 (not a regression); packets leave the VM (pktmon). No unprivileged fix exists; a WFP block needs admin (hardened service). `sandbox_hostile_windows` keeps the strict assertion and fails until decided. Reviewer recommendation: document as a Windows default-mode known limit now and add the WFP block to the hardened backend as a follow-up.
2. **HB-030**: SPEC-014 section 1 25 ms TCP-table reporting limit (no `net_allowed` event); known limit, not security.
3. **KVM / Windows Sandbox gates** need a host with nested virtualisation (WSL2/Hyper-V VM or bare-metal Linux).
4. **Hardened Windows readiness** stays unavailable (FirewallAPI writer race unaccepted); hardened Linux `fail2commit run` is refused because it uses Internet mode.
5. **FR-013 Windows GUI evidence** still missing.
6. Follow-ups listed by reviewers: two core unit tests read real `/etc` state; bounded probe failure reason; `group::` ACL entry check; CapabilityBoundingSet for the hardened unit; `F2C_SANDBOX_RELAY` honoured in production builds; macOS Seatbelt backend (P-211).
