# FR-027 WFP and proxy fix review, R2 (2026-11-14)

**Pinned implementation:** `61ad44bf030517559356bdb4b1d35b2ee619051d`, including fix `a90c6fe` and follow-up `61ad44b`; compared only with `22648966113918758a1aa898399d0c05023b1964` and review `35cb525bd58ded752b0e84db2e7bd47f13cc4f6c`. **Verdict:** WP-01 and WP-02 are source-fixed for their original triggers; WP-03 removes the blocking mutex I/O but still has a narrow post-cancellation write race; WP-04 is mitigated only among cooperating service instances. No WFP traffic-effect or Internet acceptance follows from this review.

## Dispositions and findings

### WP-01 — source-fixed; traffic effect unverified

The IPv4 condition now uses `u32::from_be_bytes([127,0,0,1])` via `proxy_loopback_address_host_order`, and the remote port remains the original host-order `u16` (`windows_wfp.rs:165-177,462-471`). Readback compares to separately written literal expectations, not the helpers (`:349-360`). Windows-only policy assertions check `0x7f000001` against the swapped `0x0100007f` and check an unswapped sample port (`:727-734`). This addresses the wrong-endpoint source defect. A real LPAC package connection to the bound proxy plus negative swapped-address/port and direct-route probes remains mandatory; readback alone cannot prove WFP classification or priority.

### WP-02 — source-fixed for pre-existing SID deletion; recovery is deliberately fail closed

`PackageGuard::install` checks for a pre-existing exact SID, writes an `owned:false` intent journal, calls `add_loopback_exemption`, then sets `exemption_added` and marks the journal owned only after the add reports success (`windows_wfp.rs:54-79`). `close` removes only when `exemption_added` is true and retains the journal on an ambiguous removal (`:378-425`). Startup recovery clears an unowned/absent record, refuses an unowned/present record, and removes an owned SID (`:647-672`); the action unit test is at `:738-755`. Journal creation now sets and reads back SYSTEM owner on the open file handle (`:527-568`; `ipc/winsec.rs:385-416`). These paths no longer delete a known pre-existing SID on the original failed-add trigger. A crash between successful OS add and `owned:true` persistence leaves an unowned/present journal and locks the service for manual reconciliation, which is a safe refusal, not successful automatic recovery. VM fault injection must check exact owner, DACL, add/readback failure, crash windows, restart and marker retention.

### WP-03 — Medium residual, pre-activation: a write attempt can occur after cancellation commits

The fix makes registered streams nonblocking and moves socket I/O outside `SocketRegistry.state` (`windows_proxy.rs:223-285`); `write_if_open_with` has a 250 ms monotonic deadline and checks the atomic `closed` flag before and after each write (`:288-325`). `shutdown_all` and `shutdown_except` store `closed=true` before socket shutdown (`:328-352`). This fixes the prior mutex-held slow-write teardown. There is still no serialization between the check at `:295` and the actual `write` call at `:307`: a bait worker can store `closed=true` in that interval, after which the first worker writes bytes before its post-write check. The injected blocked-write test (`:1309-1337`) intentionally returns a successful partial write *after* shutdown and asserts only that a second attempt is refused; it does not establish zero bytes after the cancellation point. Trigger: concurrent bait trip and in-flight write to an already-connected upstream. **Fix:** define a cancellation linearization point that prevents new syscall attempts after closure (for example, short lock or active-writer protocol around each nonblocking attempt, with no blocking I/O under the lock), and assert byte counts around a forced check/write interleaving. Internet remains gated, so this is not an active network bypass.

### WP-04 — Medium unresolved external-writer limit, pre-activation

`LoopbackConfigMutex` creates a protected named mutex, checks its owner/DACL, waits up to five seconds, and re-reads the machine-wide SID list under it (`windows/ffi.rs:1511-1606,1692-1759`). Full-list readback now requires exact SID/attribute equality instead of only a subset (`:1661-1689`), and ambiguous write/readback errors do not attempt a blind restore (`:1701-1759`). This coordinates *cooperating* service instances and surfaces errors. It is not compare-and-swap against another administrator or program using `NetworkIsolationSetAppContainerConfig` without that mutex: an external addition between this process's read and whole-list `Set` can still be overwritten, and a final list equal to this process's expected vector will not reveal the lost entry. Microsoft says the caller must preserve prior entries for [NetworkIsolationSetAppContainerConfig](https://learn.microsoft.com/en-us/windows/win32/api/netfw/nf-netfw-networkisolationsetappcontainerconfig). The limitation is not accepted as fixed by the mutex or re-read; do not enable Internet on that basis. Exact owner/DACL behavior of the newly created mutex also needs a VM check, since its descriptor supplies a DACL but no explicit owner (`ipc/winsec.rs:168-220`) and prior Win10 service-created files defaulted to Administrators ownership.

### R2-01 — Medium residual: failed journal owner setup leaves an untracked file

`write_exemption_journal` creates a new file at the final recovery path (`windows_wfp.rs:542-556`) before calling `set_owner_sid` and `verify_journal_owner` with `?` (`:557-560`). Unlike the later write/sync error branch (`:562-566`), either ownership error returns without removing the file. The caller assigns `guard.journal_path` only after this function returns successfully (`windows_wfp.rs:66`), so its rollback cannot clear the orphan. Trigger: `SetSecurityInfo` or owner readback fails after `create_new`; no exemption has been added, but a zero-byte journal blocks the next install and fails parsing on service restart (`windows_wfp.rs:623-652`), while the normal launch marker may be cleared after the contained launcher exits. **Fix:** remove or safely retain and report the created path on every pre-add journal failure, and retain the service's durable refusal if cleanup of that path fails. Inject owner-set/readback failures and verify the file, marker and restart state in the VM.
