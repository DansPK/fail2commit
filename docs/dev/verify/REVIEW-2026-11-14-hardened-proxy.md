## Prior findings and regressions

- **TE-01 — source-fixed, installed-service proof pending.** The client reads and validates a bounded reply before sending exact `F2C-RESPONSE-READ\n` (`service.rs:190-207`), and the server waits at most the request deadline for that acknowledgement on both normal and malformed-request replies before disconnecting (`:1739-1753,1924-1940,1986-2000`). The STATUS probe uses the same acknowledgement (`:544-565`). A silent or malformed peer is disconnected after the bounded wait. VM tests still need to prove response delivery, timeout, error replies, and reconnect under real scheduling.
- **TE-02 — source-fixed, installed-service proof pending.** The nonblocking connection loop distinguishes initial availability, listening, connected, and prior-client-closed states (`service.rs:230-269,1830-1888`); only `ERROR_PIPE_CONNECTED` proceeds to peer authentication. The loop sleeps on no-client states and resets `ERROR_NO_DATA`. Idle CPU and repeated connect/disconnect behavior remain VM gates.
- **TE-03 — source-fixed, failure injection pending.** After the job-tree barrier, package ACL revocation and checked WFP session close happen while the protected marker still exists (`service.rs:3119-3147`; `windows_wfp.rs:147-165`). Either failure retains the marker and latches refusal; profile unload and marker clear follow successful cleanup (`service.rs:3148-3173`). Injected revoke/close failure, restart, direct authenticated LAUNCH, and uninstall still need proof.
- **Fragmented preparation frames — source-fixed.** The bounded accumulator accepts split prefix/payload and rejects oversize/extra bytes (`service.rs:1036-1063`); both request and acknowledgement readers keep buffers across polls (`:1065-1119,1388-1408,1425-1480`). A pure accumulator unit test is present (`:4072-4104`); actual pipe fragmentation remains a VM gate.
- **Duplicate malformed Content-Length — fixed.** The shared parser again returns the first matching header's parse result (`egress.rs:119-132`), with malformed-first and valid-first duplicate regression assertions (`:176-188`). This restores the prior Linux proxy behavior; the new Windows proxy rejects duplicate or malformed lengths separately (`windows_proxy.rs:483-509`).

## New findings in the unwired Windows proxy

### PX-01 — High, pre-activation: a resolving worker can forward after a bait trip

The accept loop stops accepting once `watch.tripped()` is true (`windows_proxy.rs:213-216`), and a bait hit sets `stop` and shuts registered sockets (`:332-341`). Another worker can already be inside the synchronous resolver (`:343-349`), with no upstream socket yet registered. When that resolver returns, the worker does **not** recheck `stop` or `watch.tripped()` before connecting (`:350-380`) or writing an already buffered plain HTTP head/body to upstream (`:395-405`). `shutdown_except` only visits sockets registered at its instant (`:133-146`), so it cannot cancel an upstream socket opened afterward. Trigger: concurrent requests, one carrying bait and another held in DNS until after the trip; the latter can still transmit its buffered request. **Fix:** bind resolution, connect, registration and forwarding to a cancellation state that is checked and enforced before any upstream write, including the race with socket registration; add a deterministic paused-resolver fixture that trips bait before release and asserts zero upstream bytes/connections. Keep this as a pre-activation defect because the module has no launch call site (`hardened/mod.rs:6-7`).

### PX-02 — Medium, pre-activation: proxy drop can wait beyond its stated I/O limits

`Egress::drop` shuts sockets and joins every worker synchronously (`windows_proxy.rs:79-95`). A worker can be blocked in `resolve`, which calls `ToSocketAddrs` without a deadline (`egress.rs:101-107`; `windows_proxy.rs:343-349`); `CONNECT_TIMEOUT` is started only *after* that call (`windows_proxy.rs:358-365`). Socket shutdown cannot interrupt DNS. The request reader also uses a 10-second **per-read** timeout and never checks `stop` (`windows_proxy.rs:229-232,413-480`), so a peer that trickles bytes below that timeout can keep a registered worker alive even during drop if it races registration against `shutdown_all`. **Fix:** impose one monotonic request/resolution deadline and make teardown cancellation observable in those phases; coordinate registration with shutdown so no socket can be added after the shutdown sweep. Add a slow-resolver and slow-client teardown fixture with a bounded join assertion.

## Boundary observations and exact checks

- The production resolver returns concrete `SocketAddr` values (`egress.rs:101-107`). The proxy rejects an empty, over-32, or mixed public/private answer set before attempting any connect, then passes each *resolved address* directly to `TcpStream::connect_timeout` (`windows_proxy.rs:343-380,298-300`); there is no second hostname resolution in the production connector. This source path prevents ordinary DNS rebinding between check and connect. The mixed-answer fixture (`:810-834`) uses a test connector and does not prove real DNS behavior.
- Plain HTTP requires an absolute URI, rewrites it to origin form, strips proxy authorization/connection headers, inspects at most 8 KiB of fully framed body, and forwards only one request (`windows_proxy.rs:413-581`). CONNECT is an opaque tunnel after its initial head/body scan (`:383-393,584-625`): later tunnel bytes, including TLS payloads, are not bait-inspected. The shared `Request::parse` accepts some malformed authority/request-line forms, such as trailing text after a bracketed IPv6 literal (`egress.rs:49-95`), but the actual connection remains pinned to an all-public address. Tighten grammar before activation; no private-route bypass was established from that ambiguity.
- The proxy is declared but not called by the launcher (`hardened/mod.rs:6-7`; `windows_proxy.rs:1-5`); hardened Internet still rejects (`windows.rs:495-498`, `service.rs:3765-3769`). Loopback allowance, direct-route refusal, WFP effects, LPAC path, real DNS/CONNECT behavior, installed service transport, and account/snapshot recovery are pending VM gates. Six proxy local fixtures, 26 service tests, and two egress tests were reported by the implementation worker but were not repeated here; they do not cover PX-01/PX-02 or privileged runtime behavior.
