# SPEC-003 — Protected remote

FR-003 · TC-003 · Owner paths: receive hook, trusted approval issuer, server deployment and tests.

Ship a Rust pre-receive command for self-hosted Git. Consume all old/new/ref tuples from Git, account for quarantined objects, and reject unapproved non-fast-forward updates on configured refs. Support a separate trusted issuer operated by a maintainer or approval service, with server-side state unavailable to developer processes and standard Git credentials. For MVP use an authenticated maintainer-side command on the server to mint short-lived opaque approval tokens. Store only token verifiers, bind to repository ID, authenticated actor and the exact canonical ref-update set, and carry the token via negotiated push options. Consume atomically so concurrent requests cannot replay it. Accept that a failed attempt after consumption needs fresh approval. Missing or unsupported push options deny protected rewrites. Document actor mapping for the test transport. Add outgoing secret policy on protected refs if configured, without leaking matched values. Use disposable remote fixtures to exercise direct client bypass. GitHub uses repository rules on selected refs and platform bypass controls. A hosted GitHub App and automated hosted approval service are outside this MVP.
