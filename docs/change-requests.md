# Change requests

Material behavior decisions made during implementation, per AGENTS.md ("Log material behavior changes as change requests and continue independent work"). Each entry names its trigger, the decision and the affected requirement. The requirement baseline in docs/requirements is unchanged; these refine how it is met.

| ID | Date | Trigger | Decision | Affects |
|---|---|---|---|---|
| CR-001 | 2026-11-09 | Review W2-001: CPython `site` runs `.pth`/`sitecustomize.py` from installed wheels at every interpreter start, including fail2commit's own probe and verify runs. | fail2commit starts Python without `site` (`-S` with an explicit `sys.path`), so wheel startup code never runs inside the guard. A reviewed wheel that installs an import-bearing `*.pth`, `sitecustomize.py` or `usercustomize.py` gets an approval finding naming each file, because that code will run whenever the user next starts Python. Not a hard deny: common packages such as setuptools ship one. | FR-005, FR-008 |
| CR-002 | 2026-11-09 | Review W2-002: an interrupted or cancelled pip apply was rolled forward silently by the next unrelated install, replaying the earlier approval. | Never roll forward automatically. While a journal exists, guarded pip installs for that interpreter stop with a clear message. `fail2commit pip recover` shows the unfinished plan and either completes it after a fresh approval, or discards the journal. A cancel before apply starts changes nothing; a cancel mid-apply stops at the next wheel boundary and leaves a journal. | FR-005, FR-002 |
| CR-003 | 2026-11-09 | Review W2-008: known-malware findings were approvable with one click. | Known malware (OSV `MAL-` ids and OpenSSF malicious-packages records) is a hard `Deny` for that package. Ordinary advisories and incomplete scans stay one-time approvable as SPEC-006 states. | FR-006 |
| CR-005 | 2026-11-09 | pip re-review RP-003/RP-004: a reviewed wheel could replace pip itself or write `pyvenv.cfg`/`Lib`/`bin`/`Scripts` through the data scheme, so the guard's next interpreter start ran its code. | The guard runs pip only from a private, hash-checked snapshot taken before anything is installed. Wheels that write into `pip/`, interpreter startup paths or venv executables are a hard `Deny`. Upgrading pip itself through the guard is unsupported. | FR-005, FR-008 |
| CR-006 | 2026-11-09 | T-007b review S7B-009 and source review in docs/sandbox-windows.md §1: every usable `sandboxrs-windows 0.1.1` AppContainer path applies broad system-directory ACL grants, `FILE_ALL_ACCESS` on writable roots, and an unsandboxed, `%TEMP%`-anchored probe. | SPEC-007's Windows backend is implemented directly on `windows-sys` (AppContainer, Job Objects, handle lists, handle-based ACL grants). The unused `sandboxrs-windows` pin is removed. LPAC remains unclaimed until verified. | FR-007 |
| CR-007 | 2026-11-09 | T-007b fix: grants must anchor on a fail2commit-owned root. | Every sandbox job stage (npm, pip, `fail2commit run`) is a direct child of `<cache_dir>/sandbox-stage`. | FR-007, FR-004 |
| CR-004 | 2026-11-09 | Review W2-003/W2-004: referenced script files that could not be decoded, ran past the inspection prefix, had no recognized extension, or were dropped by archive caps produced a clean result. | Any referenced script content that is not fully inspected yields an `IncompleteScan` `Deny` for that package's scripts. Every path token in a lifecycle command is a candidate regardless of extension. | FR-006, FR-004 |
